# Spine CRM — Project Notes

Read this first, before starting any task in this folder. It's the handoff from the chat where this project was first set up on GitHub/Vercel — keep it updated as things change.

## What this is

Spine CRM is a custom-built internal CRM for Techtrus (Mike's employer), replacing a legacy Power Apps/Dataverse system. Two modules: Timesheets (field engineer time tracking, approvals) and a full sales pipeline (Accounts → Opportunities → Quotes → Sales Orders → Invoices → Payments).

## Stack

- **Frontend**: React 19 + Vite + TypeScript + Tailwind v4, in this folder.
- **Backend**: Supabase (Postgres + Auth + Row-Level Security). Schema/migrations in `supabase/migrations/`, run in order.
- **Hosting**: Vercel, auto-deploys from the `main` branch.
- **Source control**: GitHub — `github.com/mike-techtrus/spine-crm` (public repo).
- **Live URL**: `spine-crm.vercel.app`

## How Claude and Mike work together here (important constraints)

- Claude cannot push to GitHub directly — no GitHub connector is available in this environment, and device-flow CLI login (`gh auth login --web`) fails here with an HTTP 415. Claude also won't type a personal access token into git config even if Mike offers one — that's a hard credential-handling rule, not a preference. The working pattern is: **Claude edits files directly in this folder** (via the link to Mike's computer), then **Mike runs `git add -A && git commit -m "..." && git push` himself**.
- Dotfile paths (anything starting with `.`, e.g. `.github/`) can't be written directly via that file link — it's blocked as a protected path. If a change needs to land in a dotfile path, deliver the file to Mike and have him place it himself.
- `npm run dev` does **not** type-check — only `npm run build` (`tsc -b && vite build`, same as what Vercel runs) catches TypeScript errors. Always verify a build before calling a change done. A bug sat invisible in dev mode for a long time before this was understood (see below).
- `.github/workflows/build.yml` now runs `npm run build` on every push/PR via GitHub Actions, so a broken build shows up as a red X on the commit.
- Branch protection / PR-based workflow was deliberately **not** set up — Mike works solo on this for now, and Vercel already refuses to put a failed build live (confirmed in practice: a broken build just left the previous working version live, nothing broken reached real users). Revisit if other developers join.

## Recent work (as of late Oct 2026)

- **Public URL vs protected URL**: the app's public address is **`spine-crm.vercel.app`**. `spine-crm-techtrus.vercel.app` (and other deployment URLs) sit behind Vercel's own login (Deployment Protection) — Mike gets in because he's signed in to Vercel, everyone else gets a Vercel login page. Links in emails (password reset, magic link) therefore always use `publicAppUrl()` (`src/lib/appUrl.ts`), never `window.location.origin`. Supabase Auth → URL Configuration should have Site URL `https://spine-crm.vercel.app` and Redirect URLs including `https://spine-crm.vercel.app/**` and `http://localhost:5173/**`.

- **Projects — phase 3** (migration 0025): `timesheet_entries.invoice_id` marks billed days (invoice delete frees them). `create_invoice_from_timesheets(project, from, to)` makes a DRAFT invoice for the project's SO from approved, uninvoiced days in the period — one invoice line per project line (days × quoted day rate), totals by the usual VAT 20% / rebate 7.5% rule. Invoiced days are locked (`timesheet_entries_lock_invoiced`). Invoicing panel on `ProjectDetail.tsx`.
- **Projects — phase 2** (migrations 0023, 0024 = clearer over-allocation message): weekly grid on My Timesheets (`components/WeeklyTimesheet.tsx`) — one row per allocation, Mon–Sun Full/AM/PM, Save draft / Submit week. Trigger `timesheet_entries_check()` enforces: ≤1 day per person per date; project entries must be the assignee's and get `client_id` from the SO (end client, else client); submitted+approved days can't exceed `allocated_days` (drafts not counted); no submissions on complete projects; approve/reject only by project owner or admin, never your own. People can delete their own drafts. "Log other time" (old single-day form) remains for non-project time. Staff Timesheets list/detail show the project; detail hides Approve unless owner/admin.
- **Projects — phase 1** (migration 0022): `projects` (one per sales order, PRJ-00001, owner + status), `project_lines` (copied from the accepted quote's lines whose line type bills `timesheet`, by `create_project_from_sales_order()`; quoted days + day rate are the locked basis), `project_assignments` (person = `field_engineers` row, allocated days in half-day steps). `timesheet_entries.project_assignment_id` exists for phase 2. Pages: `ProjectList.tsx`, `ProjectDetail.tsx` (`/staff/projects`), "Create project / Open PRJ-…" on the Sales Order. New area key `projects` — keep `AREA_KEYS` in `supabase/functions/admin-users/index.ts` in step with `APP_AREAS`. Planned: phase 2 = timesheets against assignments with an over-allocation block (DB-enforced), owner approval, weekly grid; phase 3 = invoice from approved timesheets at the quoted rate. Suggestions offered to Mike: margin per line, "request more days", complete project → prompt to close SO.
- **Line types** (migration 0021): managed `line_types` table (Outsource Resource, Resource, Expenses, Logistics, Licensing, Hardware) with `billing` = `timesheet` (T&M — intended to be added to invoices automatically from approved timesheets when the timesheet module does invoicing; not built yet) or `manual`. `line_items.line_type` is a foreign key to `line_types.name` (on update cascade). Edited in Admin → Rate cards; quote lines keep free-text line types (past quotes untouched), with suggestions from this list.
- **Sales order invoicing status** (migration 0020): `invoicingStatus()` in types.ts gives Not invoiced / Part / Fully (±5p) / Over-invoiced / Closed and the balance (net_value − invoiced_to_date). Shown as Balance to invoice + Invoicing columns on the Sales Orders list and a panel on the Sales Order page. "Close sales order" sets `closed_at` + optional `closed_reason` (separate from the form save; Reopen clears them); closed orders hide "Create Invoice".
- **Rate cards** (migration 0019, Admin → Rate cards, `RateCardsAdmin.tsx`): `line_items` (master list, seeded from the part codes on existing quote lines), `rate_cards` (one `is_default` + custom cards) and `rate_card_prices`. `accounts.rate_card_id` picks a custom card (null = Default; set on Accounts → Edit). A custom card only prices what differs — `getPricedLineItems()` falls back to the Default price per item. The quote form's "Add from rate card…" copies line type / part code / unit cost onto the quote line (`quote_lines.line_item_id` records the source); the unit cost stays editable and later rate-card changes never touch saved quotes.
- **Print layout** (Quote + Invoice): both print through `components/PrintDocument.tsx`. `@page { margin: 0 }` in index.css stops the browser printing its own header/footer (the Spine URL/date); PrintDocument puts margins back with repeating `<thead>`/`<tfoot>` spacers and pins a `footer` to the bottom of every page (`position: fixed`). Fills the page width in portrait or landscape. `printWithTitle()` sets the PDF file name. Tested by printing to PDF with headless Edge — note `landscape:` Tailwind variants did NOT apply in print, so layouts must work in both orientations without them.
- **Invoice Print / Export PDF** (`src/pages/staff/InvoiceForm.tsx`, migration 0018): print-only block based on Techtrus's real invoices (example INV2365, Sept 2026) — logo with Invoice To (account billing name + address) under it on the left; "Invoice" + Company VAT Reg / Invoice No. / PO No. / Terms / Date on the right; then lines, payment-terms text + bank details beside Net Amount / VAT Total / Total Amount. Page footer: company registration line + "Please quote invoice number…". No status, balance, Rebate or Net value by Mike's choice. Invoices have `invoice_lines` (description/qty/unit_price) that drive Value/VAT/Total (VAT 20%, rebate 7.5%, net = total − rebate — same rule as imported data); invoices without lines print one line for their Value. Company details live in `company_settings` (single row, Admin → Invoice settings, `InvoiceSettings.tsx`) — **bank details are entered there by Mike, never put in code or migrations** (public repo). Accounts gained `billing_name`, `address_line_1/2` and an Edit panel.
- **Invoiced to date is automatic** (migration 0017): `sales_orders.invoiced_to_date` = sum of linked invoices' `net_value`, excluding cancelled/draft, kept current by a trigger on `invoices`. Read-only on the Sales Order form — don't add it back to the save payload. The form also no longer sends `timesheet_sent: null` (it was wiping that field on every save).
- **Paging on list tables**: `DataTable` shows 10 / 25 / 100 rows per page (`src/lib/usePagination.ts`, remembered per browser). The lists still load every record so search/filters/sort cover everything — `fetchAllRows` in `src/lib/api/_shared.ts` fetches past Supabase's 1000-row cap in chunks (Invoices has 1,800+). Move search/filter/sort into the database only if volumes reach tens of thousands.
- **Choosable table columns** on Opportunities, Quotes, Sales Orders and Invoices: each page defines a `COLUMNS` list (`TableColumn` in `src/lib/useColumnPrefs.ts`) rendered by `components/DataTable.tsx`; the **Columns** button (`components/ColumnPicker.tsx`) shows/hides and reorders them, saved per browser in localStorage. To offer a new field, add an entry to that page's `COLUMNS` (use `defaultHidden: true` to keep the default view unchanged).
- **Address on profiles** (migration 0016): `address_line_1`, `address_line_2`, `city`, `postcode` on `field_engineers`, edited in the profile's Details card.
- **Users tab with staff profiles** (migration 0015): the top-level "Contractors" tab is now **Users** (`/staff/users`, permission key still `engineers`) with Contractors / Staff sub-tabs (`PeopleList.tsx`, `SectionTabs.tsx`). Staff profiles live in `field_engineers` too, with `kind = 'staff'`; `day_rate` is labelled "Cost rate" for them (`PERSON_KINDS` in types.ts). Profiles are `PersonProfile.tsx` at `/staff/users/{contractors|staff}/:id`; old `/staff/engineers` links redirect. Staff linked to a staff profile get My Timesheets; TimesheetDetail blocks approving your own. Login dropdown uses `list_people_logins()`; the old `list_contractor_logins()` is still in the DB only so the previous deploy kept working — drop it in a later migration.
- **Skills database** (migration 0014): `skill_categories`, `skills` and `contractor_skills` tables, plus a CV per contractor in the private `contractor-cvs` storage bucket (`field_engineers.cv_path` etc.). The master list is managed at Admin → Skills (`src/pages/staff/admin/SkillsAdmin.tsx`, writes need `is_admin()`). Profiles are now at `/staff/users/...` (see above). Admin now has tabs (`AdminTabs.tsx`); `/staff/admin` redirects to `/staff/admin/logins`. The Admin sub-tab for accounts is called **Logins** (not Users) so it doesn't clash with the top-level Users tab.
- Contractors link to a login through a dropdown (migration 0013, `list_contractor_logins()`). `field_engineers.user_id` is unique, so one login per contractor.

- "Field Engineer" is now called **"Contractor"** everywhere on screen. Only the labels changed: the database role (`field_engineer`), table (`field_engineers`), permission key (`engineers`) and code names deliberately still say engineer. Use "Contractor" in any new UI text.
